# cubrid-client v1.3.0

A backward-compatible feature and correctness update for the TypeScript/Node.js CUBRID client. The version number describes an API release, not a certification for production use. GitHub Release and npm publication remain separate, verified steps.

## Highlights

- Add opt-in server-side prepared parameter binding while keeping the existing literal-query behavior as the default ([#207](https://github.com/cubrid-lab/cubrid-client/pull/207)).
- Add `getTables()`, `getColumns()`, `getPrimaryKey()` and `getIndexes()` for read-only schema introspection, including owner disambiguation and safe shutdown of already-started operations ([#206](https://github.com/cubrid-lab/cubrid-client/pull/206)).
- Add `isolationLevel` and `lockTimeout` client options and per-`transaction()` overrides. Settings are reapplied when a new CAS session opens; a failed setup rejects rather than running a statement under unintended defaults ([#209](https://github.com/cubrid-lab/cubrid-client/pull/209)).
- Add `stream()` for backpressured, row-by-row consumption of large SELECT results, with cancellation and cursor cleanup. `query()` remains an array-returning method ([#212](https://github.com/cubrid-lab/cubrid-client/pull/212)).
- Expose `queryResult()` column metadata, `execute()` affected-row counts and conditional last-insert IDs, server-version inspection, redacted diagnostics and explicit error classes ([#198](https://github.com/cubrid-lab/cubrid-client/pull/198), [#192](https://github.com/cubrid-lab/cubrid-client/pull/192), [#193](https://github.com/cubrid-lab/cubrid-client/pull/193), [#182](https://github.com/cubrid-lab/cubrid-client/pull/182), [#183](https://github.com/cubrid-lab/cubrid-client/pull/183)).
- Decode supported timezone-aware SQL values using `ZonedDateTime` rather than silently discarding their zone information; expose BLOB/CLOB content with documented size limits ([#204](https://github.com/cubrid-lab/cubrid-client/pull/204), [#194](https://github.com/cubrid-lab/cubrid-client/pull/194)).

## Fixes

- Reject incomplete EXECUTE and FETCH replies and retire damaged sessions rather than reporting partial or uncommitted work as successful ([#213](https://github.com/cubrid-lab/cubrid-client/pull/213), [#187](https://github.com/cubrid-lab/cubrid-client/pull/187)).
- Preserve DATE, DATETIME and TIMESTAMP years 1 through 99 instead of mapping them into 1901 through 1999; reject invalid zero dates ([#211](https://github.com/cubrid-lab/cubrid-client/pull/211), [#186](https://github.com/cubrid-lab/cubrid-client/pull/186)).
- Correct collection-column decoding and empty BIT values instead of corrupting adjacent values or fabricating data ([#167](https://github.com/cubrid-lab/cubrid-client/pull/167), [#197](https://github.com/cubrid-lab/cubrid-client/pull/197)).
- Keep query lifecycles serialized on a shared session, preserve manual transactions across health checks, and prevent transaction callbacks from issuing further statements after completion ([#169](https://github.com/cubrid-lab/cubrid-client/pull/169), [#181](https://github.com/cubrid-lab/cubrid-client/pull/181), [#164](https://github.com/cubrid-lab/cubrid-client/pull/164)).
- Reject follow-up statements after server-initiated transaction aborts, and restore connection-specific settings on replacement sessions ([#195](https://github.com/cubrid-lab/cubrid-client/pull/195), [#188](https://github.com/cubrid-lab/cubrid-client/pull/188)).
- Bound initial handshake waits, prevent queries from reopening a deliberately closed client, and preserve the CAS session when an autocommit operation does not require replacement ([#199](https://github.com/cubrid-lab/cubrid-client/pull/199), [#200](https://github.com/cubrid-lab/cubrid-client/pull/200), [#205](https://github.com/cubrid-lab/cubrid-client/pull/205)).

## Compatibility

- The declared Node.js runtime floor remains **18 and newer** for the entire 1.x line. Node.js 18 and 20 are end-of-life upstream but remain in this package's 1.x support contract. No runtime floor is raised in v1.3.0; removal requires a separately reviewed major-version decision.
- The new APIs are additive. An existing custom `ConnectionLike` implementation may omit `stream()` and `setTransactionOptions()`, but a consumer attempting to use an unsupported optional capability receives an error rather than silent fallback.
- `transaction()` provides an independent connection; the manual shared-connection transaction methods have different ownership constraints. `stream()` is not exposed on a transaction callback's `tx` object.
- `isolationLevel` accepts `read committed`, `repeatable read` and `serializable`. `lockTimeout` is milliseconds (`0` means do not wait; `-1` means no limit); behavior is defined by the database server and should not be inferred from the isolation-level name alone.
- CUBRID 10.2, 11.0, 11.2 and 11.4 were used in targeted live development tests reported in the relevant feature PRs. These developer reports are not a substitute for a successful **final release commit** validation matrix.
- `stream()` supports early termination via `break` and `return()`; consumers who drive the iterator manually must release it. The requested `fetchSize` may be ignored by the tested CAS versions. A query awaited on the same connection inside an active stream can reject with `stream-busy`.

## Known limitations

- The package does not claim complete compatibility with every CUBRID SQL type, broker configuration, failure mode or high-availability scenario. An error during a network exchange or COMMIT can have an unknown server-side result; failed writes are not blindly replayed.
- CUBRID JSON values remain represented as text rather than automatically converted to JavaScript objects. Ordinary DATE/DATETIME interpretation still depends on local time-zone semantics; timezone-aware SQL types use their separate documented representation ([#111](https://github.com/cubrid-lab/cubrid-client/issues/111), [#113](https://github.com/cubrid-lab/cubrid-client/issues/113)).
- `maxLobBytes` limits LOB reads, with different documented accounting for a fully buffered query and individual streamed rows. Applications must still enforce their own total data and memory budgets ([#93](https://github.com/cubrid-lab/cubrid-client/issues/93)).
- A stream can hold a single session while the cursor is open; concurrent work on that same connection can wait, and abandoning a manually driven iterator without `return()` can defer cleanup. Additional transaction, parity and fault-injection coverage is tracked separately ([#114](https://github.com/cubrid-lab/cubrid-client/issues/114), [#117](https://github.com/cubrid-lab/cubrid-client/issues/117), [#118](https://github.com/cubrid-lab/cubrid-client/issues/118)).
- A named PostgreSQL/MySQL feature, or a superficially similar SQL dialect behavior, is not a promise of CUBRID equivalence. Consult the package's actual protocol tests, API documentation and version support matrix.

## Validation and release scope

The individual feature PRs report offline tests, targeted real-broker checks, and selected Node 18 ESM/CJS smoke checks. These are development evidence only, not evidence that this exact v1.3.0 release commit passed all required gates. Before tagging, the reviewed release workflow requires offline tests, type checks, generated TypeScript API checks, high-severity dependency audit, packed ESM/CJS consumers on Node 18/20/22, live CUBRID 10.2/11.0/11.2/11.4 tests and real TLS checks. A skipped, blocked or `action_required` workflow is not a passing result.

A GitHub Release alone is not proof that the matching npm package exists. v1.2.0 initially had an npm authentication/publishing failure ([#166](https://github.com/cubrid-lab/cubrid-client/issues/166)), but the [2026-11-07 release-state verification run](https://github.com/cubrid-lab/cubrid-client/actions/runs/42386083795) subsequently confirmed the exact `cubrid-client@1.2.0` version on the public npm registry as well as its GitHub Release. The [exact-version release gate](https://github.com/cubrid-lab/cubrid-client/pull/219) now rejects missing or unverified prior versions instead of advancing on GitHub metadata alone. v1.3.0 still requires its own successful final-commit publish checks, the npm Trusted Publisher configuration and explicit maintainer release approval ([#120](https://github.com/cubrid-lab/cubrid-client/issues/120), [release process](https://github.com/cubrid-lab/cubrid-client/blob/main/docs/RELEASE_PROCESS.md)).

**Upgrade guidance:** evaluate the added capabilities and changed error behavior before upgrading from an earlier 1.x version. No previously published npm version is deprecated or withdrawn by these notes. Full source comparison: [v1.2.0...v1.3.0](https://github.com/cubrid-lab/cubrid-client/compare/v1.2.0...v1.3.0).
