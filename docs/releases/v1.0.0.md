# cubrid-client v1.0.0

Published: 2026-03-14. Notes corrected on 2026-11-06 against the tagged implementation; the published package and version tag are unchanged.

## Highlights

- Introduce the native TypeScript CAS protocol adapter as the default connection implementation.
- Remove the external `node-cubrid` runtime dependency from the package.
- Provide ESM and CommonJS entry points for the Promise-based TypeScript client.

## Fixes

- Replace the legacy driver's connection path with a native connection and query implementation. This is a major-version architecture change, not a promise of complete behavioral compatibility.

## Compatibility

- Declared Node.js runtime support: 18 and newer.
- A complete live CUBRID version compatibility matrix was not required by this release's CI.
- The adapter/API differences from legacy `node-cubrid` require application-level validation; do not assume it is a drop-in replacement for every legacy behavior.

## Known limitations

- Subsequent audits identified incorrect CAS type and statement identifiers, incomplete collection decoding, and gaps in unsupported-type handling. See [#81](https://github.com/cubrid-lab/cubrid-client/issues/81), [#82](https://github.com/cubrid-lab/cubrid-client/issues/82), [#110](https://github.com/cubrid-lab/cubrid-client/issues/110), and [#116](https://github.com/cubrid-lab/cubrid-client/issues/116).
- Do not use the original published coverage percentage as evidence of full wire-protocol compatibility or live broker verification.

## Validation and release scope

The tagged CI ran type checking, offline tests with coverage, and a build on Node 18/20/22. It did not require a real CUBRID integration job. Whether separate manual live checks occurred at the time is not established by this record. See [#119](https://github.com/cubrid-lab/cubrid-client/issues/119) and [#120](https://github.com/cubrid-lab/cubrid-client/issues/120).
