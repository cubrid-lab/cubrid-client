## v1.6.0 (2026-11-22)

TypeScript projects can now compile cubrid-client's published declarations without `@types/node` or the DOM lib, and a plain `Uint8Array` is now accepted wherever a `Buffer` is. For Node.js projects with `@types/node` the types are exactly what they were, and `Buffer` handling at run time is unchanged.

### Upgrade notes

- **Types without `@types/node`:** the published `.d.ts` files no longer name `Buffer`, `AbortSignal` or `node:stream`. They use two new exported types instead: `CubridBytes` is `Buffer` when the program has Node's types and `Uint8Array` otherwise, and `CubridAbortSignal` is the global `AbortSignal` when Node's types or the DOM lib are present and a minimal structural type otherwise. The declarations need `lib` `es2022` or later.
- **New compile errors in one configuration:** projects with no `@types/node` that set `skipLibCheck: true` saw `Buffer` and `AbortSignal` in the old declarations as `any`, so `QueryParam` and every `signal` option accepted anything. They are now real types, and code such as `db.query(sql, rows as unknown[])` or `const s: string = options.signal.reason` no longer compiles. Type the values (for example `rows as QueryParam[]`) or add `@types/node`. This is classed as a declaration-bug correction in a 1.x minor release; projects with `@types/node` or `skipLibCheck: false` are unaffected.
- **Plain `Uint8Array` values:** a `Uint8Array` that is not a `Buffer` was refused before. It is now accepted as a parameter of `query()`, `execute()`, `stream()`, the `*Prepared` methods and `executeMany()`, as a `clob()` source and as `ssl.ca`. It is wrapped as a `Buffer` over the same memory and sends exactly the bytes an equal `Buffer` sends. Other typed arrays and `DataView` are still refused, and returned bytes are still `Buffer`.
- **`LobParam.source`:** `BlobSource` and `ClobSource` no longer name `Readable`; a `Readable` is still accepted as an `AsyncIterable`. Code that narrows `LobParam.source` with `"pipe" in source` no longer gets a typed `Readable`; use `instanceof Readable`.
- **Known limitations:** without `@types/node`, a `signal` of the structural shape type-checks, but at run time it must still be a real `AbortSignal`. A `Uint8Array` created in another realm, such as a `vm` context, is refused.
- **Verified compatibility:** a CI step packs the package and compiles three consumers with `skipLibCheck: false`: no Node or DOM types, the DOM lib only, and `@types/node`, where `CubridBytes` and `CubridAbortSignal` must be exactly `Buffer` and `AbortSignal`. On main after the change, the live suite passed on CUBRID 10.2, 11.0, 11.2 and 11.4 (323 tests each), including a test that a plain `Uint8Array` stores the same bits as an equal `Buffer` on the literal and prepared paths. The release gate repeats the live matrix and adds real TLS, JDBC parity and packaged ESM/CJS consumers on Node.js 18 through 26 before publishing.
