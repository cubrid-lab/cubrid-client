## v1.5.0 (2026-11-22)

This release lets code inside a transaction stream rows, adds opt-in typed binds for `stream()`, and exposes the time zone that each client, pool and transaction decodes dates in. It fixes two wrong reports after server-side changes: a transaction cut off by a database server restart, and generated keys missing after a table was recreated. A rewritten socket reader uses less client CPU. Nothing is removed from the public API.

### Upgrade notes

- **Runtime and types:** Node.js 18 and newer remain supported. `TransactionClient`, `ConnectionLike` and the other capability interfaces you implement are unchanged, so custom connections and test doubles keep compiling. `PoolConnection` and `TransactionScope`, which describe objects the library provides, now extend `TimezoneAware`, and `TransactionScope` also gains `stream()`; a hand-written mock typed as one of them needs a `timezone` member (see API_STABILITY).
- **Error kind after a server restart:** the `-224` error that every statement of an open transaction gets after the database server restarts now has `kind: "connection-lost"`. Its class, `code` and `outcomeUnknown` are unchanged. Nothing commits in that case; a `CubridPool` destroys the connection instead of lending it again. Test `kind` rather than the error class, because a pool caller can see `QueryError` or `ConnectionError` for the same outage.
- **Streams inside a transaction:**
  - While a stream is open, other statements in the transaction wait, and after `consumerTimeout` they are refused with `kind: "stream-busy"` without being sent. A refusal that nothing handles blocks the commit like any failed statement. A stream created but never read sends nothing and does not block the commit.
  - Committing, or returning from the `transaction()` callback, with a stream still open aborts the stream, rolls the transaction back and rejects; partial work is never committed. `rollback()` closes the stream first.
  - A pool connection whose stream was aborted by such a refused commit is closed instead of reused.
- **Prepared streams:** `binding: "prepared"` works only on connections from the built-in adapter. A custom `connectionFactory` connection fails the first read rather than silently falling back to literals. `stream()` refuses `blob()` and `clob()` values with either binding. If the closing COMMIT of an autocommit prepared stream fails after the rows were delivered, the session is discarded instead of throwing inside your loop; use `queryPrepared()` for a SELECT whose functions write. Literal binding stays the default.
- **Generated keys:** when the server lists an inserted row without its key column, the client now sends a PREPARE of `SELECT * FROM <table>` and then reads the session's last insert id, on the same session and before COMMIT. This happens only on that reply, only for a single `INSERT` or `REPLACE` without `SELECT`, a function call or `ON DUPLICATE KEY UPDATE`, and only when the table has exactly one AUTO_INCREMENT column and every column belongs to it, so views and other owners' tables of the same name are refused. Otherwise the key stays absent as before. A `-72` error on that extra PREPARE now fails the statement.
- **Package:** the LICENSE now names "CUBRID Lab" instead of "CUBRID Labs" ([#310](https://github.com/cubrid-lab/cubrid-client/pull/310)). Package contents and the MIT license are otherwise unchanged.
- **Known limitations:**
  - ADR 0011, which names `binding`, is still Proposed; only `stream()` gains the option in 1.x.
  - A plain `Date` written to a timezone-aware column still takes the session time zone; wrap it in `zoned()` to keep its instant.
  - JSON is still returned as text.
- **Verified compatibility:** on main after the last code change, the live suite ran on CUBRID 10.2, 11.0, 11.2 and 11.4 with 322 tests passed and none skipped, including streams inside transactions and prepared streams. The `-224` restart behaviour was observed by hand on CUBRID 11.4; its automated tests are unit tests. The server sent keyless generated-key replies on 11.0, 11.2 and 11.4 and every key was recovered; 10.2 never sent one, so that path is untested there. The CPU figures for the socket reader were measured on 11.4 only. The release gate repeats the live matrix and adds real TLS, JDBC parity and packaged ESM/CJS consumers on Node.js 18 through 26 before publishing. These tests do not establish compatibility with every type, fault or broker configuration.

### Features

- Stream rows inside `transaction()` and on a `beginTransactionScope()` handle with `stream()`, including `rowMode: "array"`, and send stream parameters as typed binds with `{ binding: "prepared" }` ([#315](https://github.com/cubrid-lab/cubrid-client/pull/315)) by @yeongseon
- Read the time zone that dates are decoded in from `timezone` on the client, the pool, a `transaction()` callback's `tx`, a `beginTransactionScope()` handle, a pool connection and the built-in adapter ([#314](https://github.com/cubrid-lab/cubrid-client/pull/314)) by @yeongseon

### Bug Fixes

- Classify the `-224` error after a database server restart as `connection-lost` ([#311](https://github.com/cubrid-lab/cubrid-client/pull/311)) by @yeongseon
- Recover `generatedKeys` when the server lists the inserted row without its key column, as CUBRID 11.0, 11.2 and 11.4 can do after a table is recreated ([#313](https://github.com/cubrid-lab/cubrid-client/pull/313)) by @yeongseon

### Improvements

- Read replies through one reader per socket instead of attaching listeners for each read, cutting client CPU by about 9 to 15% per primary-key SELECT and 17 to 19% on 10,000-row reads on CUBRID 11.4, with primary-key SELECT latency unchanged ([#279](https://github.com/cubrid-lab/cubrid-client/pull/279)) by @yeongseon
