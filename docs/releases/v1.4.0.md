## v1.4.0 (2026-11-12)

This release adds a connection pool, batch execution, BLOB/CLOB writes, per-query cancellation and several safety fixes to the TypeScript/Node.js CUBRID client. Two of the fixes close SQL injection paths in the default literal parameter path.

### Upgrade notes

- **Runtime:** Node.js 18 and newer remain supported throughout 1.x. Release checks now also cover Node.js 24 and 26.
- **Parameters:** literal parameters are validated before anything is sent. A wrong number of values, values outside `QueryParam`, non-finite numbers and invalid dates now reject with `QueryError` where they were sent before. Negative numbers are sent as `(-n)` (#258).
- **Credentials:** `database`, `user` and `password` longer than 31 UTF-8 bytes, or containing NUL, are refused before connecting. Before, they were silently truncated, and a 32-byte password made of the correct 31 bytes plus any extra character could log in (#261).
- **Connection timeout:** `connectionTimeout` now defaults to 10 seconds per TCP connect, where an unset value had no limit. `0` keeps the operating-system limit. Sockets set `noDelay` and a 60-second keepalive (#262).
- **Reply size:** a reply over `maxReplyBytes`, which defaults to 1 GiB as before, now reports `The server's reply of N bytes is over the maxReplyBytes limit` instead of `Invalid CAS frame length` (#263).
- **Unobserved failures in `transaction()`:** a statement failure that nothing observes, such as `void tx.query(...)`, now always rolls the transaction back. Awaited and caught failures behave as before. A detached `.catch()` that observes a failure arriving after the callback returned now lets the transaction commit, where 1.3.0 rolled it back (#265, ADR 0009).
- **`close()` behaviour:**
  - `CubridClient.close()` waits for `transaction()` callbacks that have already started, and a callback admitted but not yet started rejects with `Client is closed.`.
  - Calling `close()` again after a failure returns the same rejected promise; `destroy()` releases what is left (#267).
  - `pool.close()` awaited inside callbacks no longer deadlocks (#269).
- **`lastInsertId`:** it is reported only when it is certain to belong to the statement. It is no longer reported for `INSERT ... SELECT`, multi-statement strings or values that call a function. `{ generatedKeys: true }` reads the statement's own key (#271).
- **Dates:** DATE, TIME, TIMESTAMP and DATETIME still decode in the process time zone by default. Set `timezone: "utc"` to read them as UTC; ADR 0010 proposes that as the 2.0 default (#272).
- **Deprecated:** `beginTransaction()`, `commit()` and `rollback()` on the client. Use `beginTransactionScope()` or `transaction()`.
- **Known limitations:**
  - A `Date` written to a timezone-aware column is stored shifted by the session time zone ([#273](https://github.com/cubrid-lab/cubrid-client/issues/273)).
  - With `generatedKeys`, CUBRID 11.x sometimes returns no key, and an INSERT trigger can fail.
  - JSON is still returned as text.
- **Verified compatibility:** live broker tests ran on CUBRID 10.2, 11.0, 11.2 and 11.4, with real TLS, JDBC parity and packaged ESM/CJS consumers on Node.js 18 through 26. Some new features were exercised live only on 10.2 and 11.4, as their pull requests state. These tests do not establish compatibility with every type, fault or broker configuration.

### Features

- Reuse connections with `createPool()`, which never reuses a session that may be in a transaction ([#260](https://github.com/cubrid-lab/cubrid-client/pull/260)) by @yeongseon
- Run one statement for many parameter sets with `executeMany()` through EXECUTE_ARRAY, atomically in autocommit ([#256](https://github.com/cubrid-lab/cubrid-client/pull/256)) by @yeongseon
- Write BLOB and CLOB values with `blob()` and `clob()` on the prepared methods, streamed in 128 KiB chunks ([#257](https://github.com/cubrid-lab/cubrid-client/pull/257)) by @yeongseon
- Cancel one statement with an `AbortSignal` or a per-query `readTimeout` ([#241](https://github.com/cubrid-lab/cubrid-client/pull/241)) by @yeongseon
- Own a manual transaction with `beginTransactionScope()`, so unrelated queries cannot join it ([#232](https://github.com/cubrid-lab/cubrid-client/pull/232)) by @yeongseon
- Decode DATE, TIME, TIMESTAMP and DATETIME as UTC with `timezone: "utc"` ([#233](https://github.com/cubrid-lab/cubrid-client/pull/233)) by @yeongseon
- Read and write Latin-1 text with the opt-in `charset: "iso-8859-1"` option ([#266](https://github.com/cubrid-lab/cubrid-client/pull/266)) by @yeongseon
- Keep every value of repeated column names with `rowMode: "array"` ([#276](https://github.com/cubrid-lab/cubrid-client/pull/276)) by @yeongseon
- Tell callers whether a failed statement may have run, with `outcomeUnknown` on errors ([#274](https://github.com/cubrid-lab/cubrid-client/pull/274)) by @yeongseon
- Tear down a stuck connection at once with `destroy()` ([#262](https://github.com/cubrid-lab/cubrid-client/pull/262)) by @yeongseon
- Bound the memory of one server reply with `maxReplyBytes` ([#263](https://github.com/cubrid-lab/cubrid-client/pull/263)) by @yeongseon

### Bug Fixes

- Stop negative literal parameters from turning the rest of the SQL into a comment, and lex literal SQL as CUBRID does so a value cannot move between markers ([#258](https://github.com/cubrid-lab/cubrid-client/pull/258)) by @yeongseon
- Refuse credentials the broker would truncate instead of logging in with a different value ([#261](https://github.com/cubrid-lab/cubrid-client/pull/261)) by @yeongseon
- Decide commit or rollback of `transaction()` by whether a failure was observed, not by microtask timing ([#265](https://github.com/cubrid-lab/cubrid-client/pull/265)) by @yeongseon
- Wait for running `transaction()` callbacks in `close()`, and stop `pool.close()` from deadlocking inside callbacks ([#267](https://github.com/cubrid-lab/cubrid-client/pull/267), [#269](https://github.com/cubrid-lab/cubrid-client/pull/269)) by @yeongseon
- Never report a stale or guessed `lastInsertId` ([#271](https://github.com/cubrid-lab/cubrid-client/pull/271)) by @yeongseon
- Quote identifiers containing `]` with backticks in `escapeIdentifier()` ([#270](https://github.com/cubrid-lab/cubrid-client/pull/270)) by @yeongseon
- End the autocommit read transaction when a FETCH fails partway ([#231](https://github.com/cubrid-lab/cubrid-client/pull/231)) by @yeongseon
